One of my personal projects is an E-Commerce Sales Insights Platform, a Power BI dashboard built for a US-based e-commerce business using around 113,000 order records. The main business objective was to give management a single interactive dashboard to monitor sales, profitability, customer and product performance, regional trends, and shipping performance, and quickly identify areas that required attention.

The raw transaction data contained fields such as Order Date, Ship Date, Customer, Product, Category, Region, State, Sales, Profit, Quantity, and Discount. I first cleaned and structured the data and created a star-schema-oriented model, with the Orders table as the fact table and supporting dimensions such as Calendar, Product, Customer Segment, Region, and State Coordinates. One challenge was deciding which attributes should remain in the fact table versus being separated into dimensions; for a production model, I would normalize these into dedicated dimension tables.

For analysis, I created KPIs such as YTD Sales, YTD Profit, YTD Quantity, Profit Margin %, Previous Year Sales, and YoY Growth %, using DAX functions such as TOTALYTD(), SAMEPERIODLASTYEAR(), and DIVIDE(). I also used ranking logic to identify Top 5 and Bottom 5 products. Customer performance was analyzed using sales and customer-segment trends; however, the project documentation does not specify a separate repeat-customer or high-value-customer segmentation methodology, so I would not claim a specific RFM model for this project.

The dashboard then presented the insights through KPI cards, monthly trends, customer-segment comparisons, state-level maps, Top/Bottom product charts, regional analysis, and shipping-mode analysis, with slicers for interactive filtering. From a business perspective, these insights could help management identify high-performing products and regions, declining segments, and areas where marketing or operational attention was needed.

A Power BI workspace is the collaborative environment where reports, semantic models, dashboards, and other Power BI content are developed and managed. A Power BI App is a packaged, controlled way of distributing selected content from a workspace to business users.

A report is a multi-page interactive Power BI document containing visuals, filters, drill-through, and other interactions, while a dashboard is a single-page canvas in Power BI Service made up of pinned tiles. In my project, I developed multi-page reports and provided executives with KPI dashboard views.

For navigation, drill-down allows users to move to a more detailed level within the same visual — for example, Year → Quarter → Month → Day. Drill-through takes the user to a separate detail page while carrying the selected filter context. I used drill-down for time-based analysis and drill-through for detailed DC or stockout investigation.

I used bookmarks when I wanted to provide different report views without creating separate pages. For example, my dashboard used a bookmark to toggle between stockout and excess-inventory views with a button.
